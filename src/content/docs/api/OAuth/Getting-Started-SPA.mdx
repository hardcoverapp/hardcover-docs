This guide will walk you through the steps for making a simple Single Page App (SPA) application using hardcover OAuth, this is going to be a basic example, and there are a bunch of improvements you can make, but this is the bare bones.

If you're building a server-rendered app or a backend-for-frontend instead, see the [confidential client guide](/api/oauth/getting-started-server). Building a CLI tool, desktop app, or anything else without a browser tab to redirect through? See the [native/device guide](/api/oauth/getting-started-device). Not sure which fits? Check [Which flow do I need?](/api/oauth#which-flow-do-i-need)

## Setting up the app

You first need to acquire an app, head over to the <a href={URLS.NEW_DEVELOPER_APP_URL} target="_blank" rel="noreferrer noopener">New Developer App</a> page.

For this guide you only need to set the Application Type, Name, OAuth Redirect URI and Scopes.

<ImageComponent imagePath="/src/content/images/api/oauth/new_app_spa.png" description="Creating a new app, select Single-page app." />

<ImageComponent imagePath="/src/content/images/api/oauth/new_app_name.png" description="Name the app something, this is shown to your users!" />

<ImageComponent imagePath="/src/content/images/api/oauth/new_app_spa_oauth.png" description="OAuth information, the redirect URI's and allowed scopes." />

For this guide you will only need the `read:me:content` scope, but you can set whatever scopes you need.
And I will be using `python -m http.server` to serve it, so I am setting the Redirect URI to `http://localhost/` and `http://localhost/index.html`. Since this is loopback (localhost) the port does not matter, but if you are going to host this publicly you will have to use https, and if you are not using port 443 (omitted by default) you will have to specify the port.

After you click create you will be taken to the apps info page, when you are here, copy the client ID, this is how hardcover will know what app is doing the authentication.

## Step 0: Discovery

To do OAuth, the first thing you have to do is know where you have to call.

For the sake of this Guide we will be hard coding the endpoints, but the info you need can be found at the <a href={URLS.OAUTH_DISCOVERY_URL} target="_blank" rel="noreferrer noopener">OAuth Discovery Endpoint</a>. You can fetch it dynamically, so the app will still work even if in the future we change the locations.

```javascript
// Values can come from discovery
// https://api.hardcover.app/.well-known/oauth-authorization-server
const AUTHORIZE_ENDPOINT = "https://hardcover.app/oauth2/authorize";
const TOKEN_ENDPOINT = "https://api.hardcover.app/oauth2/token";
const REVOKE_ENDPOINT = "https://api.hardcover.app/oauth2/revoke";
const GRAPHQL_ENDPOINT = "https://api.hardcover.app/v1/graphql";
const ISSUER = "https://api.hardcover.app";
```

## Step 1: Prepping secrets

The first step is to generating the secrets needed for the flow.

The spec asks for the `verifier` to be between 43 and 128 characters long, this is because it wants a minimum of 256 bits (32 bytes) of entropy, and when you base64url encode that you get 43 characters.


```javascript
const state = randomString(24);
const verifier = randomString(32);
const challenge_code = await sha256(verifier);
```

Store the PKCE verifier and the state, we will be needing them in step 4.
```javascript
sessionStorage.setItem("pkce_verifier", verifier);
sessionStorage.setItem("oauth_state", state);
```

## Step 2: Sending off the user

Here are the parameters we are going to be sending the authentication server.

```javascript
const queryParams = new URLSearchParams({
  response_type: "code",
  client_id: CLIENT_ID,
  redirect_uri: REDIRECT_URI,
  state: state,
  code_challenge: challenge_code,
  code_challenge_method: "S256",
  scope: SCOPE,
});
```

The important ones we haven't mentioned are:
##### `client_id`
The client's public ID, for this example you can use mine, but if you want a different domain then localhost, or more permission then identifying the user, you will need to make your own app.

```javascript
const CLIENT_ID = "64003fc6-9a33-4787-b80b-4827f40d46c6";
```

##### `redirect_uri`
Tells hardcover which of our pre approved redirect URIs to send the user to after they finish.

```javascript
const REDIRECT_URI = location.origin + location.pathname;
```

##### `scope`
Which of our pre approved permissions do we want. In this case we just want to be able to get the user id, username, name, and profile image.
The publicly available user information

```javascript
const SCOPE = "read:me:content";
```

##### Others
`response_type` and `code_challenge_method` do not have any other options.
For the response type "code" means that we want a code that we can exchange for the key back.
And for the challenge method "S256" means we used SHA256 to hash the secret, so the server knows what to use when verifying.


Since this is a barebones example, so we don't have any fancy open in new tab or opening a window just for the OAuth flow then closing it, we are just redirecting the user in the same tab.
Though think those over for your own implementations since they make for a much nicer user experience.

So off they go!

```javascript
location.href = `${AUTHORIZE_ENDPOINT}?${queryParams}`;
```

## Step 3: User approval

The user has now landed on the consent screen, they are given the option to approve or deny access to your app.

<ImageComponent imagePath="/src/content/images/api/oauth/spa_auth_consent.png" description="OAuth consent screen, asking if the user is ok with giving 'SPA demo app' access to their public profile fields." />

Once the user has consented to your app, the consent screen will not show up again for an entire year, as long as you only request the same or a subset of the consented scope, if you want a scope they have not consented to, then the user will be shown the consent screen again upon going through the flow.

## Step 4: The user is back

The user is redirected back to your website!

There are now 2 possibilities:
- The user has the `error` query param set. Meaning the user was either rejected your app or the sign-in has failed (in which case you will also have a `error_description`).
- The user has the `code` param set, in that case we can continue with step 4.

First you want to fetch the secrets we stored earlier, we will now make use of them. And lets clean up after ourselves.

```javascript
const state = sessionStorage.getItem("oauth_state");
const verifier = sessionStorage.getItem("pkce_verifier");
sessionStorage.removeItem("oauth_state");
sessionStorage.removeItem("pkce_verifier");

history.replaceState({}, "", REDIRECT_URI); // drop ?code= so a refresh can't replay it
```

And now we can begin our checks.

First lets make sure we have a verifier code stored and that state matches, if this is wrong it means the user probably started multiple login flows and we somehow have the wrong one (or there was an attacker trying to fake us out). Either way, stop.

```javascript
if (!verifier || params.get("state") !== state) {
  render({
    signedIn: false,
    message: "Sign-in failed: unexpected callback. Try again.",
  });
  return;
}
```

Hardcover sets `authorization_response_iss_parameter_supported`, so every callback names the server that issued the code (RFC 9207). Check it.

If your app supports more than one provider, this is what stops a malicious one from handing you a code that you then redeem at another provider's token endpoint (a mix-up attack). State can't catch that, because the state is legitimately yours.

```javascript
const ISSUER = "https://api.hardcover.app";
```

```javascript
if (params.get("iss") !== ISSUER) {
  render({
    signedIn: false,
    message: "Sign-in failed: response came from the wrong issuer.",
  });
  return;
}
```


## Step 5: Getting the real tokens

You now are sure that you are the one that sent off the user, and that the data they returned with is real, it is time to trade the `code` that the user came back with for a real OAuth token!

We only sent the hash with the user, and Hardcover is now waiting for the code that hashes to it to prove the client is really the same one who initiated the transaction. That's all PKCE is.

```javascript
const res = await fetch(TOKEN_ENDPOINT, {
  method: "POST",
  headers: { "Content-Type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({
    grant_type: "authorization_code",
    code: params.get("code"),
    redirect_uri: REDIRECT_URI, // must match step 2 exactly
    client_id: CLIENT_ID,
    code_verifier: verifier,
  }),
});
const token = await res.json().catch(() => ({}));

if (!res.ok) {
  // Read this one. Nearly every first-run failure lands here, usually a redirect_uri that doesn't match what's registered.
  render({
    signedIn: false,
    message: `Sign-in failed: ${token.error_description ?? token.error ?? res.status}`,
  });
  return;
}
```

The response for the server has 3 items:
| Field | Description |
| --- | --- |
| `access_token` | in the shape of `hc_at_xxxx`, your API Bearer token. |
| `refresh_token` | in the shape of `hc_rt_xxxx`, the token you can use in the same token endpoint with the `refresh_token` grant type to get a new set of tokens. |
| `expires_in` | when the access token will expire, you will still be able to use the refresh token, but the access token will no longer be valid. |


Now for storing the token `localStorage` is not the most secure option, but it will work for this demo.

```javascript
localStorage.setItem("oauth_token", token.access_token);
```

For this example we wont be implementing the refresh functionality, we will only so we will only be storing the access token.

## Step 6: Use the API

That's it. You're all set. You now have an API token that you can use to make request, for example, getting the user info.

```javascript
const res = await fetch(GRAPHQL_ENDPOINT, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${accessToken}`,
  },
  body: JSON.stringify({
    query: "{ me { id username name image { url } } }",
  }),
});
const body = await res.json().catch(() => ({}));
const user = body.data?.me?.[0];
```

## Wrapping up

One final thing before we go, when signing out, you could technically just delete the tokens from your storage, no one else has them, so the user is now signed out.

However, hardcover tracks the sessions, so the user will see on their authorized apps page that your app still has an active or idle session. So it is recommended to revoke the tokens when signing out.

```javascript
fetch(REVOKE_ENDPOINT, {
  method: "POST",
  headers: { "Content-Type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({
    token: accessToken,
    token_type_hint: "access_token",
    client_id: CLIENT_ID,
  }),
}).catch(() => {});
```

You can use either the access token or the refresh token, it does not matter, they are revoked together.


## Full code

Full example code, save both files somewhere and then serve them using something like `python -m http.server`

```html
<!-- index.html -->
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Hardcover OAuth demo</title>
</head>
<body>
  <button id="sign-in">Sign in with Hardcover</button>
  <button id="sign-out" hidden>Sign out</button>
  <p id="status" role="status"></p>

  <script src="./oauth.js"></script>
</body>
</html>
```

```javascript
// oauth.js

const CLIENT_ID = "64003fc6-9a33-4787-b80b-4827f40d46c6";

// Values can come from discovery
// https://api.hardcover.app/.well-known/oauth-authorization-server
const AUTHORIZE_ENDPOINT = "https://hardcover.app/oauth2/authorize";
const TOKEN_ENDPOINT = "https://api.hardcover.app/oauth2/token";
const REVOKE_ENDPOINT = "https://api.hardcover.app/oauth2/revoke";
const GRAPHQL_ENDPOINT = "https://api.hardcover.app/v1/graphql";
const ISSUER = "https://api.hardcover.app";

const REDIRECT_URI = location.origin + location.pathname;

const SCOPE = "read:me:content";

const signInBtn = document.getElementById("sign-in");
const signOutBtn = document.getElementById("sign-out");
const statusEl = document.getElementById("status");

// helpers

// Modern browsers can use `Uint8Array.prototype.toBase64({ alphabet: "base64url" })`
// But since it was was only added to all browsers in 2025 https://caniuse.com/mdn-javascript_builtins_uint8array_tobase64
// We will be using btoa and replacing the chars needed to get to the url alphabet, also dropping the padding
const base64url = (bytes) =>
  btoa(String.fromCharCode(...bytes))
    .replaceAll("+", "-")
    .replaceAll("/", "_")
    .replace(/=+$/, "");

const randomString = (byteLength) =>
  base64url(crypto.getRandomValues(new Uint8Array(byteLength)));

async function sha256(input) {
  const digest = await crypto.subtle.digest(
    "SHA-256",
    new TextEncoder().encode(input),
  );
  return base64url(new Uint8Array(digest));
}

// ui helper

function render({ signedIn, message }) {
  statusEl.textContent = message;
  signInBtn.hidden = signedIn;
  signOutBtn.hidden = !signedIn;
}

// entry point

function main() {
  signInBtn.addEventListener("click", signIn);
  signOutBtn.addEventListener("click", signOut);

  const params = new URLSearchParams(location.search);
  const savedToken = localStorage.getItem("oauth_token");

  if (params.has("error")) {
    // The user declined, or the app is misconfigured.
    history.replaceState({}, "", REDIRECT_URI);
    render({
      signedIn: false,
      message: `Sign-in failed: ${params.get("error_description") ?? params.get("error")}`,
    });
  } else if (params.has("code")) {
    handleCallback(params);
  } else if (savedToken) {
    showProfile(savedToken); // still signed in from a previous visit
  }
}

// step 1/2: prep and send the user

async function signIn() {
  const state = randomString(24);
  const verifier = randomString(32);
  const challenge_code = await sha256(verifier);

  sessionStorage.setItem("pkce_verifier", verifier);
  sessionStorage.setItem("oauth_state", state);

  const queryParams = new URLSearchParams({
    response_type: "code",
    client_id: CLIENT_ID,
    redirect_uri: REDIRECT_URI,
    state: state,
    code_challenge: challenge_code,
    code_challenge_method: "S256",
    scope: SCOPE,
  });

  location.href = `${AUTHORIZE_ENDPOINT}?${queryParams}`;
}

// step 4: catch and verify the user

async function handleCallback(params) {
  const state = sessionStorage.getItem("oauth_state");
  const verifier = sessionStorage.getItem("pkce_verifier");
  sessionStorage.removeItem("oauth_state");
  sessionStorage.removeItem("pkce_verifier");

  history.replaceState({}, "", REDIRECT_URI); // drop ?code= so a refresh can't replay it

  if (!verifier || params.get("state") !== state) {
    render({
      signedIn: false,
      message: "Sign-in failed: unexpected callback. Try again.",
    });
    return;
  }

  if (params.get("iss") !== ISSUER) {
    render({
      signedIn: false,
      message: "Sign-in failed: response came from the wrong issuer.",
    });
    return;
  }

  // step 5: trade for the token

  const res = await fetch(TOKEN_ENDPOINT, {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body: new URLSearchParams({
      grant_type: "authorization_code",
      code: params.get("code"),
      redirect_uri: REDIRECT_URI, // must match step 2 exactly
      client_id: CLIENT_ID,
      code_verifier: verifier,
    }),
  });
  const token = await res.json().catch(() => ({}));

  if (!res.ok) {
    // Read this one. Nearly every first-run failure lands here, usually a redirect_uri that doesn't match what's registered.
    render({
      signedIn: false,
      message: `Sign-in failed: ${token.error_description ?? token.error ?? res.status}`,
    });
    return;
  }

  localStorage.setItem("oauth_token", token.access_token);
  showProfile(token.access_token);
}

// step 6: use the token

async function showProfile(accessToken) {
  const res = await fetch(GRAPHQL_ENDPOINT, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${accessToken}`,
    },
    body: JSON.stringify({
      query: "{ me { id username name image { url } } }",
    }),
  });
  const body = await res.json().catch(() => ({}));
  const user = body.data?.me?.[0];

  if (!user) {
    // Usually a saved token that has expired or been revoked since last visit.
    localStorage.removeItem("oauth_token");
    render({
      signedIn: false,
      message: "Your session expired. Sign in again.",
    });
    return;
  }

  render({
    signedIn: true,
    message: `Signed in as ${user.name} (@${user.username})`,
  });
}

async function signOut() {
  const accessToken = localStorage.getItem("oauth_token");
  localStorage.removeItem("oauth_token");
  render({ signedIn: false, message: "Signed out." });

  // Optional, but tells the server the token is dead now instead of leaving
  // it valid until it expires.
  if (accessToken) {
    fetch(REVOKE_ENDPOINT, {
      method: "POST",
      headers: { "Content-Type": "application/x-www-form-urlencoded" },
      body: new URLSearchParams({
        token: accessToken,
        token_type_hint: "access_token",
        client_id: CLIENT_ID,
      }),
    }).catch(() => {});
  }
}

main();
```
