This guide will walk you through making a confidential client, an app that runs on a server you control (server-rendered, or a backend-for-frontend behind an SPA), using hardcover OAuth. Like the [SPA guide](/api/oauth/getting-started-spa) this is a bare bones example, there's a bunch of hardening you'd want to add for production, but this is the shape of it.

The thing that makes a client confidential rather than public is that it can hold a secret: a client secret issued alongside your `client_id` that only your server ever sees. That's also the only real difference from the SPA flow, everything else (PKCE, `state`, checking `iss`) still applies, confidential clients included.

## Setting up the app

Head over to the <a href={URLS.NEW_DEVELOPER_APP_URL} target="_blank" rel="noreferrer noopener">New Developer App</a> page and create an app.

For this guide you only need to set the Application Type (pick "Web app (server-side)"), Name, OAuth Redirect URI and Scopes.

<ImageComponent imagePath="/src/content/images/api/oauth/new_app_name.png" description="Name the app something, this is shown to your users!" />

Once you create it you'll be shown a client secret, this is only ever shown once (unless you rotate it). Copy it into wherever your server reads secrets from (an env var, a secret manager, etc.) never commit it into your repo.

For this guide you will only need the `read:me:content` scope. The examples run a plain HTTP server on `localhost:8080`, so the Redirect URI is `http://localhost:8080/callback`, since this is loopback it's fine over `http`, if you're hosting this for real you'll need `https`.

## Step 0: Discovery

To do OAuth, the first thing you have to do is know where you have to call.

For the sake of this guide we will be hard coding the endpoints, but the info you need can be found at the <a href={URLS.OAUTH_DISCOVERY_URL} target="_blank" rel="noreferrer noopener">OAuth Discovery Endpoint</a>. You can fetch it dynamically, so the app will still work even if in the future we change the locations.

```python
# Values can come from discovery
# https://api.hardcover.app/.well-known/oauth-authorization-server
AUTHORIZE_ENDPOINT = "https://hardcover.app/oauth2/authorize"
TOKEN_ENDPOINT = "https://api.hardcover.app/oauth2/token"
REVOKE_ENDPOINT = "https://api.hardcover.app/oauth2/revoke"
GRAPHQL_ENDPOINT = "https://api.hardcover.app/v1/graphql"
ISSUER = "https://api.hardcover.app"
```

## Step 1: Prepping secrets

Even though this client can keep a secret, we still do PKCE, Hardcover requires it on every client, confidential included.

The spec asks for the `verifier` to be between 43 and 128 characters long, this is because it wants a minimum of 256 bits (32 bytes) of entropy, and when you base64url encode that you get 43 characters.

```python
state = random_string(24)
verifier = random_string(32)
code_challenge = base64url_sha256(verifier)
```

Unlike the SPA (where the same page just reloads), sending the user off means the *next* request your server sees is a fresh one to `/callback`, with none of these local variables still around. So `state` and the verifier need to be kept somewhere your server can find them again, a real app would key this off the user's session, stored in a cookie.

```python
pending[state] = verifier
```

## Step 2: Sending off the user

Here are the parameters we are going to be sending the authentication server.

```python
params = urllib.parse.urlencode(
    {
        "response_type": "code",
        "client_id": CLIENT_ID,
        "redirect_uri": REDIRECT_URI,
        "state": state,
        "code_challenge": code_challenge,
        "code_challenge_method": "S256",
        "scope": SCOPE,
    }
)
```

The important ones we haven't mentioned are:
##### `client_id` and `client_secret`
Unlike the SPA guide, you can't reuse my demo app's `client_id` here, a confidential client needs a `client_secret` only your server has, so you'll need to have made your own app in the step above.

```python
# Client secret lives on the server only! It must never reach the browser
def must_env(name):
    value = os.environ.get(name)
    if not value:
        sys.exit(f"missing required env var {name}")
    return value


CLIENT_ID = must_env("HARDCOVER_CLIENT_ID")
CLIENT_SECRET = must_env("HARDCOVER_CLIENT_SECRET")
```

##### `redirect_uri`
Tells hardcover which of our pre approved redirect URIs to send the user to after they finish.

```python
HOST = f"http://localhost:{PORT}"
REDIRECT_URI = f"{HOST}/callback"
```

##### `scope`
Which of our pre approved permissions do we want. In this case we just want to be able to get the user id, username and name.

```python
SCOPE = "read:me:content"
```

##### Others
`response_type` and `code_challenge_method` do not have any other options.
For the response type "code" means that we want a code that we can exchange for the key back.
And for the challenge method "S256" means we used sha256 to hash the secret, so the server knows what to use when verifying.

So off they go!

```python
self.redirect(f"{AUTHORIZE_ENDPOINT}?{params}")
```

## Step 3: User approval

The user has now landed on the consent screen, they are given the option to approve or deny access to your app.

<ImageComponent imagePath="/src/content/images/api/oauth/conf_auth_consent.png" description="OAuth consent screen, asking if the user is ok with giving 'SPA demo app' access to their public profile fields." />

Once the user has consented to your app, the consent screen will not show up again for an entire year, as long as you only request the same or a subset of the consented scope, if you want a scope they have not consented to then they will be shown the consent screen again upon going through the flow.

## Step 4: The user is back

The user's browser is redirected back to your `redirect_uri`, the user is now back, and they come with some query parameters.

There are now 2 possibilities, either the request will have the `error` query param set, in that case the user has either rejected or the sign up has failed (in which case you will also have an `error_description`).

Or, the request has the `code` param set, in that case we can continue. Grab `code`, `state`, and `iss` off of it before moving on.

```python
state = q.get("state", "")
with pending_lock:
    verifier = pending.pop(state, None)
```

And now we can begin our checks.

First lets make sure `state` actually matches and that a `code` came back, if this is wrong it means the user probably started multiple login flows, the state expired, or there was an attacker trying to fake us out. Either way, stop.

```python
if verifier is None or not q.get("code"):
    return self.send_html(400, "sign-in failed: unexpected callback, try again")
```

Hardcover sets `authorization_response_iss_parameter_supported`, so every callback names the server that issued the code (RFC 9207). Check it.

If your app supports more than one provider, this is what stops a malicious one from handing you a code that you then redeem at another provider's token endpoint (a mix-up attack). State can't catch that, because the state is legitimately yours.

```python
if q.get("iss") != ISSUER:
    return self.send_html(
        400, "sign-in failed: response came from the wrong issuer"
    )
```

## Step 5: Getting the real tokens

You now are sure that you are the one that sent off the user, and that the data they came back with is real, it is time to trade the `code` for a real OAuth token.

This request is the one place a confidential client actually behaves differently, alongside the PKCE `code_verifier` we also authenticate the request itself with `client_id`/`client_secret` over HTTP Basic auth. The verifier proves this is the same backend that sent the user off in step 2, the secret proves it's really your backend at all.

```python
resp = requests.post(
    TOKEN_ENDPOINT,
    auth=(CLIENT_ID, CLIENT_SECRET),
    data={
        "grant_type": "authorization_code",
        "code": q["code"],
        "redirect_uri": REDIRECT_URI,  # must match step 2 exactly
        "code_verifier": verifier,
    },
)
token = resp.json()

if not resp.ok:
    # Read this one. Nearly every first-run failure lands here, usually a redirect_uri that doesn't match what's registered
    return self.send_html(
        502, f"sign-in failed: {token.get('error_description', '')}"
    )
```

The response for the server has 3 items:
| Field | Description |
| --- | --- |
| `access_token` | in the shape of `hc_at_xxxx`, your API Bearer token. |
| `refresh_token` | in the shape of `hc_rt_xxxx`, the token you can use in the same token endpoint with the `refresh_token` grant type to get a new set of tokens. |
| `expires_in` | when the access token will expire, you will still be able to use the refresh token, but the access token will no longer be valid. |

Since we are running in a trusted environment, we can either store and use the tokens locally, or we can just keep the refresh token and give the access token to the frontend to use however it wants.

```python
with tokens_lock:
    tokens[session] = {
        "access_token": token["access_token"],
        "refresh_token": token["refresh_token"],
        "expires_at": time.time() + token["expires_in"],
    }
```

## Step 6: Use the API

That's it. You're all set. You now have an API token that you can use to make requests, for example, getting the user info.

```python
resp = requests.post(
    GRAPHQL_ENDPOINT,
    headers={"Authorization": f"Bearer {access_token}"},
    json={"query": "{ me { id username name } }"},
)
result = resp.json()
me = result.get("data", {}).get("me") or []
```

## Wrapping up

One final thing before we go, when signing out, you could technically just drop the tokens from wherever you stored them, no one else has them, so the user is now signed out.

However, hardcover tracks the sessions, so the user will see on their authorized apps page that your app still has an active or idle session. So it is recommended to revoke the tokens when signing out.

```python
threading.Thread(
    target=lambda: requests.post(
        REVOKE_ENDPOINT,
        auth=(CLIENT_ID, CLIENT_SECRET),
        data={
            "token": token["refresh_token"],
            "token_type_hint": "refresh_token",
        },
    )
).start()
```

You can use either the access token or the refresh token, it does not matter, they are revoked together.

Also, since you're a confidential client you also have the [introspection endpoint](/api/oauth#endpoints) available, useful if you ever want to check whether a token is still valid without spending an API call to find out.

## Full code

To run the full demo you will need to have `requests` installed, you will also need `HARDCOVER_CLIENT_ID` and `HARDCOVER_CLIENT_SECRET` set as environment variables (you can get them by making a new confidential app).


```python
# main.py

import base64
import hashlib
import os
import secrets
import sys
import threading
import time
import urllib.parse
from http import cookies
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

import requests

# Values can come from discovery
# https://api.hardcover.app/.well-known/oauth-authorization-server
AUTHORIZE_ENDPOINT = "https://hardcover.app/oauth2/authorize"
TOKEN_ENDPOINT = "https://api.hardcover.app/oauth2/token"
REVOKE_ENDPOINT = "https://api.hardcover.app/oauth2/revoke"
GRAPHQL_ENDPOINT = "https://api.hardcover.app/v1/graphql"
ISSUER = "https://api.hardcover.app"

PORT = 8080


# Client secret lives on the server only! It must never reach the browser
def must_env(name):
    value = os.environ.get(name)
    if not value:
        sys.exit(f"missing required env var {name}")
    return value


CLIENT_ID = must_env("HARDCOVER_CLIENT_ID")
CLIENT_SECRET = must_env("HARDCOVER_CLIENT_SECRET")

HOST = f"http://localhost:{PORT}"
REDIRECT_URI = f"{HOST}/callback"

SCOPE = "read:me:content"


def random_string(n_bytes):
    return base64.urlsafe_b64encode(secrets.token_bytes(n_bytes)).rstrip(b"=").decode()


def base64url_sha256(verifier):
    digest = hashlib.sha256(verifier.encode()).digest()
    return base64.urlsafe_b64encode(digest).rstrip(b"=").decode()


# Stand-in for wherever you actually keep sessions (a DB row, a signed http-only cookie, etc.) Global + in-memory so this stays a single file
# Probably better to key off of session, but this makes it simpler for the demo
tokens_lock = threading.Lock()
tokens = {}  # session -> {"access_token", "refresh_token", "expires_at"}

# One pending login per state value
pending_lock = threading.Lock()
pending = {}  # state -> verifier


class Handler(BaseHTTPRequestHandler):
    def get_session(self):
        jar = cookies.SimpleCookie(self.headers.get("Cookie", ""))
        return jar["session"].value if "session" in jar else ""

    def send_html(self, status, body):
        self.send_response(status)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.end_headers()
        self.wfile.write(body.encode())

    def redirect(self, location):
        self.send_response(302)
        self.send_header("Location", location)
        self.end_headers()

    def do_GET(self):
        path = urllib.parse.urlparse(self.path).path
        if path == "/":
            self.handle_home()
        elif path == "/login":
            self.handle_login()
        elif path == "/callback":
            self.handle_callback()
        elif path == "/logout":
            self.handle_logout()
        else:
            self.send_response(404)
            self.end_headers()

    def handle_home(self):
        session = self.get_session()
        if not session:
            return self.send_html(200, '<a href="/login">Sign in with Hardcover</a>')

        with tokens_lock:
            token = tokens.get(session)

        if not token:
            return self.send_html(200, '<a href="/login">Sign in with Hardcover</a>')

        if token["expires_at"] < time.time():
            # Handle refresh here
            return self.send_html(
                200, 'Your session expired. <a href="/login">Sign in again</a>.'
            )

        profile = fetch_profile(token["access_token"])
        if profile is None:
            # Usually a saved token that has been revoked since last visit
            with tokens_lock:
                tokens.pop(session, None)
            return self.send_html(
                200, 'Your session expired. <a href="/login">Sign in again</a>.'
            )

        name, username = profile
        self.send_html(
            200, f'Signed in as {name} (@{username}). <a href="/logout">Sign out</a>'
        )

    # step 1/2: prep and send the user

    def handle_login(self):
        state = random_string(24)
        verifier = random_string(32)
        code_challenge = base64url_sha256(verifier)

        with pending_lock:
            pending[state] = verifier

        params = urllib.parse.urlencode(
            {
                "response_type": "code",
                "client_id": CLIENT_ID,
                "redirect_uri": REDIRECT_URI,
                "state": state,
                "code_challenge": code_challenge,
                "code_challenge_method": "S256",
                "scope": SCOPE,
            }
        )

        self.redirect(f"{AUTHORIZE_ENDPOINT}?{params}")

    # step 4: catch and verify the user

    def handle_callback(self):
        query = urllib.parse.parse_qs(urllib.parse.urlparse(self.path).query)
        q = {k: v[0] for k, v in query.items()}

        if "error" in q:
            # The user declined, or the app is misconfigured
            return self.send_html(
                400, f"sign-in failed: {q.get('error_description', '')}"
            )

        state = q.get("state", "")
        with pending_lock:
            verifier = pending.pop(state, None)

        if verifier is None or not q.get("code"):
            return self.send_html(400, "sign-in failed: unexpected callback, try again")

        if q.get("iss") != ISSUER:
            return self.send_html(
                400, "sign-in failed: response came from the wrong issuer"
            )

        # step 5: trade for the token

        resp = requests.post(
            TOKEN_ENDPOINT,
            auth=(CLIENT_ID, CLIENT_SECRET),
            data={
                "grant_type": "authorization_code",
                "code": q["code"],
                "redirect_uri": REDIRECT_URI,  # must match step 2 exactly
                "code_verifier": verifier,
            },
        )
        token = resp.json()

        if not resp.ok:
            # Read this one. Nearly every first-run failure lands here, usually a redirect_uri that doesn't match what's registered
            return self.send_html(
                502, f"sign-in failed: {token.get('error_description', '')}"
            )

        # Set a session so we know who they are
        session = random_string(32)
        self.send_response(302)
        self.send_header("Location", "/")
        self.send_header("Set-Cookie", f"session={session}; HttpOnly")
        self.end_headers()

        with tokens_lock:
            tokens[session] = {
                "access_token": token["access_token"],
                "refresh_token": token["refresh_token"],
                "expires_at": time.time() + token["expires_in"],
            }

    def handle_logout(self):
        session = self.get_session()
        if not session:
            return self.redirect("/")

        with tokens_lock:
            token = tokens.pop(session, None)

        # Optional, but tells the server the token is dead now instead of leaving it valid until it expires
        if token and token.get("refresh_token"):
            threading.Thread(
                target=lambda: requests.post(
                    REVOKE_ENDPOINT,
                    auth=(CLIENT_ID, CLIENT_SECRET),
                    data={
                        "token": token["refresh_token"],
                        "token_type_hint": "refresh_token",
                    },
                )
            ).start()

        self.redirect("/")

    def log_message(self, format, *args):
        pass  # keep stdout clean


# step 6: use the token


def fetch_profile(access_token):
    resp = requests.post(
        GRAPHQL_ENDPOINT,
        headers={"Authorization": f"Bearer {access_token}"},
        json={"query": "{ me { id username name } }"},
    )
    result = resp.json()
    me = result.get("data", {}).get("me") or []

    if not me:
        return None
    return me[0]["name"], me[0]["username"]


if __name__ == "__main__":
    print(f"listening on {HOST}")
    ThreadingHTTPServer(("", PORT), Handler).serve_forever()
```
