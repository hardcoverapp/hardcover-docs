`@hardcover/sdk` is the official TypeScript client for the Hardcover API. It
runs in Node 22.12+, browsers, Deno, Bun and React Native, with no
dependencies. It handles what every app would otherwise repeat: signing users
in and keeping their tokens fresh, rate limits, retries, and typed results and
errors.

<Aside type="note">
The SDK is in its 0.x releases: everything works against the live API, and
names may still change before 1.0 based on what people building with it tell
us. [Open an issue](https://github.com/hardcoverapp/community-sdk/issues) with
anything that gets in your way.
</Aside>

## Install

```sh
npm install @hardcover/sdk
```

## Quick start

Create a client with a [personal access token](/api/getting-started/), then
call any resource. Every example on these pages can be run right here with
your own token.

```ts
import { HardcoverClient, UserBookStatus } from "@hardcover/sdk";

const hc = new HardcoverClient({ token: process.env.HARDCOVER_TOKEN, userAgent: "my-app/1.0" });

const me = await hc.me.get();
const reading = await hc.library.list({ status: UserBookStatus.CurrentlyReading });
```

Keep personal access tokens out of source control and out of browser bundles.
Apps that act for other people sign them in with OAuth instead.

## Signing people in

`@hardcover/sdk/oauth` signs people in with [OAuth](/api/oauth/) and keeps
their tokens working: it refreshes them before they expire, never spends a
refresh token twice, stores each new pair before using it, and tells you once
when the person needs to sign in again. You decide where tokens are stored.

```ts
import { HardcoverClient } from "@hardcover/sdk";
import { OAuthSession, secureStore } from "@hardcover/sdk/oauth";

const session = new OAuthSession({
  clientId: "your-client-id",
  redirectUri: "yourapp://oauth/callback",
  store: secureStore(SecureStore, "hardcover-tokens"), // Keychain / Keystore
  onSignedOut: () => showSignIn(),
});
const hc = new HardcoverClient({ auth: session });

const attempt = session.authorize({ scopes: ["read:me:content", "read:library"] });
// Open attempt.url in a browser, then hand the redirect back:
await session.completeAuthorization(redirectUrl, attempt);
```

TVs and command-line tools use `session.signInWithDevice(...)`, which shows a
short code to enter at hardcover.app/link.

## Errors

Every failure is a typed error. The ones apps usually handle:

| Error | Means |
|---|---|
| `ScopeError` | The token lacks a scope; `missingScopes` lists them. |
| `RateLimitError` | Too many requests; `retryAfterSeconds` says how long to wait. |
| `SignedOutError` | An OAuth sign-in ended; show sign-in again. |
| `NotFoundError` | Something the method needed doesn't exist. |
| `NetworkError`, `ServerError` | Reads are already retried; writes are never sent twice. |

## Rate limits

The client paces itself from the API's rate-limit headers, so a burst of calls
waits instead of failing, and it backs off when other apps share your budget.
Pass `batch: true` to send concurrent reads as one request.

## Reading stats

`@hardcover/sdk/stats` computes a reader's stats for a year, a month or their
whole history, the same way the Stats page on hardcover.app does. See
[Stats](/sdk/typescript/resources/stats/).

```ts
import { readingStats, period } from "@hardcover/sdk/stats";

const year = await readingStats(hc, period.thisYear({ timeZone: "America/Denver" }));
```

## Testing

`MockTransport` from `@hardcover/sdk/testing` drives a real client with
canned responses, so your tests exercise the same code your app runs.
