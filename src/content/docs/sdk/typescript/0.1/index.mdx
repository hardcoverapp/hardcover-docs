`@hardcover/sdk` is the official TypeScript client for the Hardcover API. It
runs in Node 22.12+, browsers, Deno, Bun and React Native, with no
dependencies. It handles what every app would otherwise repeat: signing users
in and keeping their tokens fresh, rate limits, retries, and typed results and
errors.

New here? [Getting started](/sdk/typescript/0.1/getting-started/) installs it
from npm and makes a first call.

## Errors

Every failure is a typed error. The ones apps usually handle:

| Error | Means |
|---|---|
| `ScopeError` | The token lacks a scope; `missingScopes` lists them. |
| `RateLimitError` | Too many requests; `retryAfterSeconds` says how long to wait. |
| `SignedOutError` | An OAuth sign-in ended; show sign-in again. |
| `NotFoundError` | Something the method needed doesn't exist. |
| `NetworkError`, `ServerError` | Reads are already retried; writes are never sent twice. |

## Rate limits

The client paces itself from the API's rate-limit headers, so a burst of calls
waits instead of failing, and it backs off when other apps share your budget.
Pass `batch: true` to send concurrent reads as one request.

## Reading stats

`@hardcover/sdk/stats` computes a reader's stats for a year, a month or their
whole history, the same way the Stats page on hardcover.app does. See
[Stats](/sdk/typescript/0.1/resources/stats/).

```ts
import { readingStats, period } from "@hardcover/sdk/stats";

const year = await readingStats(hc, period.thisYear({ timeZone: "America/Denver" }));
```

## Testing

`MockTransport` from `@hardcover/sdk/testing` drives a real client with
canned responses, so your tests exercise the same code your app runs.

```ts
import { MockTransport } from "@hardcover/sdk/testing";
```
